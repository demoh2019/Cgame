# Cgame: experimental continuous edge–edge soft-body contact prediction

## Purpose and comparison

Jolt's architecture documentation distinguishes rigid-body `LinearCast`
continuous collision detection from its work-in-progress soft bodies:
native Jolt soft bodies do **not** provide soft-body versus soft-body
collision handling. Cgame has been adding opt-in CPU vertex/vertex,
vertex/triangle, edge/edge, face BVH, and speculative vertex/face contacts.
The **edge–edge** pass remains discrete in those earlier implementations.

This change adds a separate opt-in **conservative advancement**
sweep for two **linearly moving deformable segments**. It handles a fast
edge passing across a second edge between 60 Hz physics ticks even when
no vertex is near the other mesh's triangles.

This is not a port of Bullet or PhysX and not exact CCD for the actual
nonlinear deformable motion generated by Jolt's substep constraints.

## Enable

Project Settings > Physics > Jolt Physics 3D > Simulation:

- `soft_body_soft_contacts = true` (required; default false)
- `soft_body_soft_vertex_face_contacts = true` (required; preserves VF)
- `soft_body_soft_edge_edge_contacts = true` (required; default false)
- `soft_body_soft_speculative_edge_ccd = true` (**new**, default false)
- `soft_body_soft_ccd_max_sweep = 1.0` metres (existing 0..4 clamp)
- `soft_body_soft_ccd_max_correction_speed = 128.0` metres/s
- `soft_body_soft_contact_radius = 0.1` metres
- `soft_body_soft_contact_max_particle_pairs = 32768`

The existing `soft_body_soft_speculative_ccd` enables the *other* vertex-face
swept solver; it is independent of this edge-edge setting.

## Algorithm

1. Extract and deduplicate actual surface edges, reusing two scratch
   buffers and the existing mask/exception and world-AABB filters.
2. Expand the segment AABB queries and body broadphase by the maximum
   user-configured sweep horizon when this option is active.
3. For a candidate pair, calculate current closest segment points via the
   Ericson clamped-segment algorithm. If already touching, use the old
   discrete response.
4. For an initially separate pair, calculate an upper bound on relative
   speed as the largest speed of the **four possible endpoint-velocity
   differences**. For linear endpoint trajectories, every barycentrically
   interpolated edge-point relative speed is no greater than this bound.
5. Reject unchanging, invalid, or out-of-range motion, including relative
   displacement beyond `max_sweep`.
6. Iteratively advance time by **(closest distance − contact radius) /
   maximum relative speed**. This is a conservative increment: in exact
   arithmetic the edges cannot close the entire gap sooner. Evaluate the
   true closest segment points at each advanced time.
7. Stop at the earliest detected contact shell (finite tolerance for
   floating-point) or reject when beyond the physics step.
8. Compute contact normal at predicted contact, interpolate the four
   endpoint velocities at the predicted closest parameters and apply
   **equal-and-opposite mass-weighted speculative impulses** with a
   capped normal-velocity correction. Do not apply penetration recovery
   before impact. The original friction and pinned-endpoint handling
   remains unchanged.

A maximum **16 conservative-advancement iterations per candidate**
prevents runaway loops. The existing CPU work budget is split between
vertex-face and edge-edge passes, and *each* speculative iteration debits
another unit from the edge budget. As with the previous algorithm, the
sort/unique extraction of both edge lists is charged too. No extra heap
allocation occurs in the candidate/iteration loop.

## Limitations

- Only assumes **linear endpoint trajectories over one physics step**.
  Jolt's spring constraints, collisions, gravity, rotations and
  integration may alter these paths; this does not guarantee no
  tunneling in the full nonlinear simulation.
- It is a *speculative velocity impulse*, not time-of-impact rewind or
  substep constraint projection.
- May miss grazing/tangential contacts, extremely high speed beyond
  configured max sweep, contacts after the CPU budget runs out, and
  highly nonlinear crossings.
- A single current-body AABB expanded by max sweep is conservative only
  for motion within that configured bound.
- No self-collision, edge BVH, cloth tearing, cluster collisions, or FEM.
- A very large horizon reduces culling and can hurt CPU time.
- Native C++ compilation, actual simulation and FPS/RAM tests must be
  completed before recommending production use.

## Tests

Python reference math (not native proof):

    python3 -m unittest tests/stress/test_jolt_soft_soft_edge_sweep.py -v

Headless physics test using compiled Cgame Jolt:

    ./bin/godot.linuxbsd.editor.dev.x86_64 --headless \
      --path tests/stress/jolt_soft_soft_edge_sweep \
      --script res://swept_edges_regression.gd

The native fixture compares a fast crossing edge with an identical
collision-masked control and checks finite state, dynamic edge impulse
transfer and unchanged pinned vertices. Native test wiring is part of
`whole-engine-stress.yml`. Do not claim speedups or native passing
without a successful workflow run or local engine executable.

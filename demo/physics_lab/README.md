# Cgame Physics Lab — интерактивные демо-карты 3D и 2D

Отдельный Godot-проект внутри исходников Cgame. Цель — вручную проверять
физические сценарии, сравнивать бэкенды и быстро воспроизводить регрессии.
Демо ничего не меняет в настройках других проектов и не нуждается во внешних
ассетах. Вся геометрия и физические объекты создаются скриптами при запуске.

## Бэкенд физики

В `project.godot` карта **явно** выбирает `GodotPhysics3D`. Это
необходимо для проверки расширений XPBD/FEM в ядре Cgame: движок Jolt
имеет более высокий приоритет по умолчанию и не использует эти настройки.
Чтобы отдельно сравнивать Jolt, создайте копию проекта и выберите
`physics/3d/physics_engine="Jolt Physics"`. Не делайте выводы о
работоспособности native XPBD по запуску сцены на Jolt.

## Нативная вода для SoftBody3D

Для новых гидростатических сил, интегрируемых прямо в C++-солвере,
смотри отдельную сцену [SoftBody Hydrostatic Lab](../softbody_hydrostatic_lab/README.md).
Она специально выбирает `GodotPhysics3D`, включает плоскость воды
и сравнивает два замкнутых мягких куба разной массы. В отличие от
скриптовой воды Physics Lab, гидростатическая нагрузка зависит от
погружённой площади, глубины и деформируемой геометрии.

## Запуск

1. Соберите Cgame с редактором (или используйте его готовый исполняемый файл).
2. В Project Manager выберите **Import** и укажите
   `demo/physics_lab/project.godot`; затем запустите проект (**F6/F5**).
3. Либо из корня репозитория выполните:
   ```bash
   godot --path demo/physics_lab --editor
   godot --path demo/physics_lab
   ```
   Имя исполняемого файла зависит от платформы и конфигурации сборки.

   **macOS (Apple Silicon или Intel)**, если команда `godot` не найдена:
   ```bash
   # Выполняется из корня Cgame
   git checkout develop && git pull origin develop
   python3 -m pip install scons
   scons platform=macos target=editor arch=$(uname -m) -j$(sysctl -n hw.ncpu)
   ./bin/godot.macos.editor.$(uname -m) --path demo/physics_lab
   ```
   Если бинарник уже собран, команду SCons можно пропустить. Для редактора
   добавьте `--editor`, для smoke-теста `--headless --script res://smoke_test.gd`.
   Это исполняемый файл **Cgame**, не стандартного Godot.


По умолчанию открывается 3D-полигон. **F1** или кнопка в панели переключает
на 2D и обратно. **R** сбрасывает физический мир. На обеих сценах есть счётчик
FPS, количество динамических тел, события датчиков и результат физического луча.

### XPBD-пределы деформации в SoftBody3D

3D-станция **04 SoftBody3D** дополнительно использует новую систему
ограничения деформаций в Cgame при выборе бэкенда **GodotPhysics3D**.
Встроенные в *этот демо-проект* настройки:

- `physics/3d/solver/soft_body_xpbd_strain_max_stretch_ratio = 1.5` —
  ограничивает удлинение рёбер до 150% текущей длины покоя.
- `physics/3d/solver/soft_body_xpbd_strain_min_compression_ratio = 0.6` —
  не допускает сжатие рёбер ниже 60% длины покоя.
- `physics/3d/solver/soft_body_xpbd_strain_limit_compliance = 0` —
  жёсткие односторонние ограничения XPBD; положительное значение делает
  их мягче, масштабируя податливость на квадрат шага симуляции.

Оба первых параметра по умолчанию равны `0` в обычных проектах:
дополнительных буферов и проходов тогда нет. Параметры задаются на уровне
проекта и читаются при создании физического мира, поэтому после изменения
настроек перезапустите сцену/игру. Они не добавляют FEM или разрыв ткани.
Полностью совпавшее положение вершин не имеет определённого направления
для восстановления ограничения и пока требует дополнительной обработки.

### Нелинейная мембранная физика StVK

Станция **04 SoftBody3D** проверяет новую опциональную модель
*St. Venant–Kirchhoff surface membrane*, работающую с физическим
бэкендом GodotPhysics3D. В `project.godot` только для лаборатории
включены:

- `physics/3d/solver/soft_body_xpbd_membrane_compliance = 0.00001`
- `physics/3d/solver/soft_body_membrane_poisson_ratio = 0.3`

Для обычных проектов мембранная податливость равна `0`, что
полностью отключает подготовку rest-metric, добавочную память и
мембранные итерации. Модель учитывает сопряжённые деформации
растяжения, сжатия и сдвига (тензор Грина–Лагранжа), а также
коэффициент Пуассона. Это **тонкая поверхностная мембрана**,
не FEM тетраэдрального объёма: она не моделирует разрывы,
толщину материала, пластиковые складки или контакт внутри объёма.
Жёсткость определяется через XPBD compliance, а не через
непосредственно задаваемый модуль Юнга в паскалях. После изменения
настроек нужно перезапустить проект, чтобы физический мир создал
буферы с новыми параметрами.

**Новое вязкоупругое демпфирование мембраны.** В лаборатории также
установлено `physics/3d/solver/soft_body_membrane_damping_rate = 3.0`
(единица измерения — `1/с`). При нулевом значении дополнительный
проход полностью отключён. В отличие от глобального воздушного
сопротивления, демпфер подавляет лишь скорость изменения
внутриплоскостной деформации (растяжение и сдвиг), сохраняя
поступательное движение и вращение поверхности. Расчёт использует
локальные градиенты тензора деформации, учитывает обратные массы и
не двигает закреплённые вершины. Это проекционный вязкоупругий
демпфер, **не** полная калиброванная модель Kelvin–Voigt.

Дополнительные тесты: `tests/servers/test_physics_softbody_membrane_damping.cpp`
и `tests/stress/test_physics_softbody_membrane_damping.py`.

Для проверки Python-референса: `python3 -m unittest discover -s tests/stress -p test_physics_xpbd_membrane.py -v`.
Нативные случаи: `tests/servers/test_physics_xpbd_membrane.cpp`.

### Импорт явной тетраэдральной сетки

На **04 SoftBody3D** добавлен оранжевый образец `FEMConcaveImportedTwoTets`:
замкнутая **невыпуклая** оболочка с пятью физическими вершинами,
шестью треугольниками и двумя вручную заданными тетраэдрами.
Обычная автоматическая схема выпуклого разбиения эту форму отклоняет.

В Cgame GodotPhysics3D появилось свойство узла `SoftBody3D.tetrahedral_indices`
типа `PackedInt32Array`. Указываются **четвёрки индексов вершин
визуальной поверхности**, например:

```gdscript
var body := SoftBody3D.new()
body.tetrahedral_indices = PackedInt32Array([0, 1, 2, 3, 0, 2, 1, 4])
body.mesh = my_closed_triangle_mesh
```

Физический сервер автоматически сопоставляет визуальные индексы с
общими (welded) физическими узлами. Список хранится в узле сцены и
сохраняется при пересоздании сетки. Если список пуст, работает
старое автоматическое разбиение выпуклой оболочки.

Валидатор требует замкнутую и одинаково ориентированную внешнюю
оболочку, положительные объёмы каждого элемента, попарное совпадение
внутренних граней с противоположной ориентацией, **точное совпадение
граничных тетраэдральных треугольников** с треугольниками поверхности
и совпадение суммарного объёма. Повреждённый импорт отключает FEM,
не затрагивая обычный SoftBody3D. Максимум 4096 тетраэдров.
Проверяется и сама сетка, но полное обнаружение геометрических
самопересечений между непересекающимися по индексам элементами
пока отсутствует: исходные тетраэдры должны быть корректно
подготовлены во внешнем mesher'е.

**Ограничения:** на этом этапе импортированные тетраэдры ссылаются
на узлы самой треугольной оболочки; отдельные внутренние вершины
simulation mesh, независимая collision mesh, поверхность с другими
диагоналями граничных граней и embedding визуальной геометрии пока
не поддерживаются. API работает в движке **GodotPhysics3D**;
другие physics backends вправе игнорировать эту экспериментальную
опцию. Настройки FEM по умолчанию выключены.

Тесты: `tests/servers/test_physics_fem_explicit_tetra.cpp`,
`tests/stress/test_physics_fem_explicit_tetra.py` и CI workflow
`physics-fem-explicit-tetra.yml`.

### Многотетраэдральная FEM-физика

На станции **04 SoftBody3D** добавлен отдельный бирюзовый куб
`FEMConvexCubeSixTets` с восемью общими индексируемыми вершинами
и замкнутыми ориентированными гранями. Новая экспериментальная
Neo-Hookean FEM-подсистема строит для него **шесть тетраэдров**
из выпуклой поверхностной сетки и решает их общим проходом XPBD.

В демо-проекте включены параметры:

- `physics/3d/solver/soft_body_tetra_fem_compliance = 0.00002`
- `physics/3d/solver/soft_body_tetra_fem_lumped_mass = true` — новые
  объёмно-зависимые массы узлов (в обычных проектах `false`).
- `physics/3d/solver/soft_body_tetra_fem_poisson_ratio = 0.3`
- `physics/3d/solver/soft_body_tetra_fem_viscosity = 0.8` — независимое
  объёмное вязкоупругое демпфирование скоростей деформации тетраэдров.

В обычном проекте FEM compliance = `0`, поэтому не выполняются
ни подготовка тетраэдров, ни дополнительные проходы решателя.

**Масса FEM-узлов.** При включении объёмного распределения каждый
невырожденный тетраэдр добавляет `density × rest_volume / 4` к массе
каждой из четырёх вершин. Суммарная масса тела сохраняется, но
вершины, прилегающие к большему объёму, получают больше массы.
Закреплённые вершины остаются кинематическими; при откреплении
восстанавливается именно их FEM-масса. Изменение `total_mass`
масштабирует узлы, не разрушая их массовые пропорции.
При неудачной подготовке или выключении опции возвращаются
равномерные массы предыдущего решателя. Масса зависит от объёма
**сетки симуляции**, а не от толщины видимой поверхности.
Новый численный модуль: `servers/physics_fem_lumped_mass.h`,
проверки: `tests/stress/test_physics_fem_lumped_mass.py` и
`tests/servers/test_physics_fem_lumped_mass.cpp`.

**Ограничения и безопасность:** автоматическое разбиение доступно
только для замкнутой, последовательно ориентированной, **выпуклой**
треугольной поверхности с количеством вершин не более 2048
и треугольников не более 4096. Сначала проверяется замкнутость,
потом выпуклость относительно граней, затем корректность каждого
тетраэдра и суммарного объёма. Не прошедшая проверку сетка сохраняет
обычный solver мягкого тела без FEM. Важно: произвольные
невыпуклые объёмы, материал с разрывами, полностью произвольные
сетки из тетраэдров, физически выверенное распределение массы и
GPU FEM пока не поддерживаются.

Численные проверки: `tests/stress/test_physics_fem_convex_star.py`;
нативные C++-тесты: `tests/servers/test_physics_fem_convex_star.cpp`.

## Усталостные повреждения мягких тел

В Physics Lab включён экспериментальный `XPBD fatigue damage`:
при повторяющемся сильном сжатии или растяжении связи мягкого тела
постепенно ослабевают. Попробуйте в `project.godot` переключить
`3d/solver/soft_body_fatigue_damage_rate` между `0.0` и `0.8`
и сравните деформацию SoftBody3D. Эффект **не разрывает сетку**.
Подробные настройки приведены в
[ADVANCED_SOFT_MATERIALS.md](ADVANCED_SOFT_MATERIALS.md).

## Направленный XPBD-изгиб ткани

Складывание ткани вдоль и поперёк волокон теперь имеет **независимую**
жёсткость — помимо уже имеющейся анизотропии растяжения. В этом
демонстрационном проекте включены базовый угловой XPBD-солвер
(`soft_body_xpbd_dihedral_compliance=0.00001`) и направленная
податливость `soft_body_xpbd_bend_parallel_compliance_ratio=0.2`.
Оба параметра настраиваются в разделе `[physics]` файла
`project.godot`; другие проекты Cgame сохраняют изотропный изгиб,
пока настройка явно не изменена.

Рекомендация для сравнения: менять только новое отношение `0.2 ↔ 1.0`,
не трогая сетку, физический шаг, массу и параметры растяжения.
Модель работает через нативные диэдральные ограничения GodotPhysics3D.
См. [ADVANCED_SOFT_MATERIALS.md](ADVANCED_SOFT_MATERIALS.md).

## Анизотропные мягкие материалы (нативная физика)

Для ткани и мягких объектов добавлена отдельная направленная жёсткость
при растяжении. В `project.godot` этого демонстрационного проекта включены
`soft_body_xpbd_compliance=0.00005`,
`soft_body_xpbd_parallel_compliance_ratio=0.2`, направление волокна
`Vector3(1, 0, 0)`. По умолчанию в других проектах Cgame значение
пропорции равно `1.0` (обычный изотропный XPBD).

Попробуйте изменить `0.2` на `1.0` и перезапустить сцену — при одинаковой
геометрии ткань должна иначе сопротивляться вытягиванию вдоль локальной X.
Подробности и тесты: [ADVANCED_SOFT_MATERIALS.md](ADVANCED_SOFT_MATERIALS.md).
Работает только с бэкендом **GodotPhysics3D**, не с Jolt.

| Конвейер [I] | StaticBody3D с `constant_linear_velocity` и шероховатым материалом у (−14, 24) | StaticBody2D с движущимся контактным слоем над полом |
| Локальная гравитация [G] | Area3D со сменой направления гравитации на вверх | Area2D с собственной гравитацией |
| Разрушение [L] | Тестовый куб разбивается на 8 физических фрагментов от сильного удара | Тестовый блок разбивается на 4 фрагмента |
| Направление конвейера [;] | Реверс движения ленты | Реверс движения ленты |

В нижнем правом углу сцен есть отдельная панель advanced с включением
станций, настройкой силы вихря, скорости конвейера и запуском теста удара.
Для сброса фрагментов и тел нажмите **R**. Клавиша **Tab** циклически
перемещает камеру по нескольким точкам обзора, в том числе к новым станциям. Настройки действуют только
внутри тестовой карты.

**Ограничения моделирования:** вихрь — приближённая центростремительная
и тангенциальная сила, конвейер передаёт скорость контактам, а разрушение
заменяет целое тело заранее заданными фрагментами. Это не объёмный солвер
вихревой жидкости, не автоматическая генерация трещин и не FEM.
Фрагменты сохраняются до перезапуска сцены, поэтому при нагрузочном
тестировании следите за количеством тел и FPS.

## Проверка загрузки и выполнения

```bash
godot --headless --path demo/physics_lab --script res://smoke_test.gd
```

Smoke-тест загружает обе сцены, выполняет по 40 физкадров с изменением сил, проверяет
наличие ключевых узлов и динамических тел, возвращает код 0 при успехе.
Запускать его нужно локально на собранной версии Cgame. Он не заменяет
визуальную проверку, профилирование и регрессионные тесты solver'а.

## Сравнение физических движков

3D-бэкенд выбирается в **Project → Project Settings → Physics → 3D →
Physics Engine**. Например, можно прогонять одни и те же сцены на
GodotPhysics3D и Jolt Physics, **если оба встроены в текущую сборку**.
После смены бэкенда перезапустите проект и сравнивайте FPS, устойчивость
стопок/суставов, поведение CCD и деформации. В 2D используется
доступный бэкенд GodotPhysics2D (или другой, если он реализован в сборке).

### Важные ограничения

- **Это набор репрезентативных сценариев, а не обещание 100% покрытия**
  всех подсистем физики Cgame. Рэгдоллы, сложное разрушение, FEM, жидкостная
  SPH/FLIP-симуляция, ткань со швами, многослойные ландшафты, все типы
  joints и runtime-генерация concave mesh здесь пока не представлены.
- Вода — **приближённая пользовательская физика** в `environment_3d.gd` и
  `environment_2d.gd`: силы Архимеда, сопротивление, течение и синусоидальное
  колебание уровня при контакте с телами. Это **не** CFD/SPH/FLIP-солвер:
  нет переноса объёма, брызг с частицами, сохранения массы жидкости и
  корректного подсчёта погруженного объёма для наклонённых мешей.
- Ветер и магнит также реализованы как игровые силы на физических телах,
  а не полноценные аэродинамика и электромагнитный симулятор.
- Силы, задаваемые обработчиками демонстрации, действуют только в Physics Lab;
  глобальные физические настройки остальных игр Cgame не изменяются.
- Из-за различий реализации PhysicsServer3D некоторые функции, в том числе
  SoftBody3D и VehicleBody3D, могут вести себя по-разному на разных бэкендах.
  Такие различия — предмет проверки, а не гарантированное одинаковое поведение.
- Повторяйте стресс-тест с разным числом тел и записывайте FPS, время
  физкадра и RAM через встроенный Profiler; один FPS без baseline
  не доказывает улучшение производительности.

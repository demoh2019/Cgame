# Cgame Physics Lab — интерактивные демо-карты 3D и 2D

Отдельный Godot-проект внутри исходников Cgame. Цель — вручную проверять
физические сценарии, сравнивать бэкенды и быстро воспроизводить регрессии.
Демо ничего не меняет в настройках других проектов и не нуждается во внешних
ассетах. Вся геометрия и физические объекты создаются скриптами при запуске.

## Запуск

1. Соберите Cgame с редактором (или используйте его готовый исполняемый файл).
2. В Project Manager выберите **Import** и укажите
   `demo/physics_lab/project.godot`; затем запустите проект (**F6/F5**).
3. Либо из корня репозитория выполните:
   ```bash
   godot --path demo/physics_lab --editor
   godot --path demo/physics_lab
   ```
   Имя исполняемого файла зависит от платформы и конфигурации сборки.

По умолчанию открывается 3D-полигон. **F1** или кнопка в панели переключает
на 2D и обратно. **R** сбрасывает физический мир. На обеих сценах есть счётчик
FPS, количество динамических тел, события датчиков и результат физического луча.

### Станции 3D

| № | Сценарий | Что проверяем |
|---|---|---|
| 1 | Башня из блоков и тяжёлый шар | Контакты, устойчивость стопок, массы |
| 2 | Наклонная рампа и шары | Качение, столкновения, движение по наклонам |
| 3 | PinJoint3D, HingeJoint3D, SliderJoint3D | Маятник, цепь, шарнир, слайдер и constraint solver |
| 4 | SoftBody3D над препятствием | Деформация меша, столкновения мягкого тела |
| 5 | Водный бассейн с интерактивными телами | Плавучесть, плотность, погружение, сопротивление, течение, изменение уровня и волны |
| 6 | Быстрые шары против тонкой стены | CCD включено и выключено, сравнение туннелирования |
| 7 | Шары с разными PhysicsMaterial | Трение и упругость |
| 8 | VehicleBody3D с четырьмя колёсами | Подвеска и колесные контакты |
| 9 | Area3D, RayCast3D, ShapeCast3D | Сигналы пересечения и запросы коллизий |
| 10 | Ветер и магнит | Направленные силы, притяжение/отталкивание металлических тел и стресс +100 |

### Станции 2D

| № | Сценарий | Что проверяем |
|---|---|---|
| 1 | Башня RigidBody2D | Стэкинг, массы, контакты |
| 2 | Две наклонные платформы и круги | Упругость, трение, наклоны |
| 3 | PinJoint2D и GrooveJoint2D | Цепь, маятник и осевое ограничение |
| 4 | DampedSpringJoint2D + Area2D | Пружина, локальная обратная гравитация, пересечения |
| 5 | Тонкая стенка, CCD-шар, CharacterBody2D | Быстрые столкновения, move_and_slide, RayQuery2D и ShapeCast2D |

На 2D-полигоне также размещены отдельный бассейн с плавучестью и течением, ветер и магнит.

### Управление

| 3D | Действие |
|---|---|
| Зажать ПКМ + мышь | Осматриваться (Esc освобождает курсор) |
| WASD, Q / E, Shift | Полёт камерой, вниз/вверх, ускорение |
| B | Бросить динамический куб из камеры |
| C | Запустить два быстрых шара (CCD on/off) |
| Пробел | Импульс для всех RigidBody3D |
| X | Добавить 100 тел на stress-площадку |
| ЛКМ по объекту (держать) | Захват и перенос динамического тела пружинной силой |
| F | Толкнуть выбранный курсором объект |
| P | Радиальный взрыв в точке прицела |
| V / T | Включить ветер / повернуть направление на 45° |
| M / N | Магнит / смена полярности (притяжение ↔ отталкивание) |
| O | Сбросить новый куб в бассейн |
| J / U | Понизить / повысить уровень воды |
| Y | Включить / выключить колебания поверхности |
| K | Цикл гравитации: 1.0 → 0.0 → -0.6 → 1.0 |
| Z | Заморозить захваченный объект |
| Стрелки / Ctrl | Газ и поворот автомобиля / тормоз |
| F1 / R | Переключить 2D / перезапустить сцену |

В **2D**: WASD перемещает камеру, колесо масштабирует, B создаёт шар,
C запускает CCD-шар, Space подбрасывает динамические тела, X создаёт
100 тел, F1 переключает в 3D, R перезапускает сцену.
ЛКМ позволяет хватать и перетаскивать динамические тела. F толкает выбранный
объект, P создаёт импульс взрыва вокруг курсора, V/T включают и направляют
ветер, M переключает магнит, O создаёт объект над бассейном,
J/U регулируют глубину воды, Y переключает волны, K циклически меняет
гравитацию и Z замораживает захваченное тело.

В верхнем правом углу обоих полигонов расположена панель с кнопками и
ползунками: сила ветра, уровень/глубина и плотность воды, течение, масса
создаваемого тела, включение сил. Можно менять параметры прямо во время
симуляции, без перезапуска сцены.

## Проверка загрузки и выполнения

```bash
godot --headless --path demo/physics_lab --script res://smoke_test.gd
```

Smoke-тест загружает обе сцены, выполняет по 40 физкадров с изменением сил, проверяет
наличие ключевых узлов и динамических тел, возвращает код 0 при успехе.
Запускать его нужно локально на собранной версии Cgame. Он не заменяет
визуальную проверку, профилирование и регрессионные тесты solver'а.

## Сравнение физических движков

3D-бэкенд выбирается в **Project → Project Settings → Physics → 3D →
Physics Engine**. Например, можно прогонять одни и те же сцены на
GodotPhysics3D и Jolt Physics, **если оба встроены в текущую сборку**.
После смены бэкенда перезапустите проект и сравнивайте FPS, устойчивость
стопок/суставов, поведение CCD и деформации. В 2D используется
доступный бэкенд GodotPhysics2D (или другой, если он реализован в сборке).

### Важные ограничения

- **Это набор репрезентативных сценариев, а не обещание 100% покрытия**
  всех подсистем физики Cgame. Рэгдоллы, сложное разрушение, FEM, жидкостная
  SPH/FLIP-симуляция, ткань со швами, многослойные ландшафты, все типы
  joints и runtime-генерация concave mesh здесь пока не представлены.
- Вода — **приближённая пользовательская физика** в `environment_3d.gd` и
  `environment_2d.gd`: силы Архимеда, сопротивление, течение и синусоидальное
  колебание уровня при контакте с телами. Это **не** CFD/SPH/FLIP-солвер:
  нет переноса объёма, брызг с частицами, сохранения массы жидкости и
  корректного подсчёта погруженного объёма для наклонённых мешей.
- Ветер и магнит также реализованы как игровые силы на физических телах,
  а не полноценные аэродинамика и электромагнитный симулятор.
- Силы, задаваемые обработчиками демонстрации, действуют только в Physics Lab;
  глобальные физические настройки остальных игр Cgame не изменяются.
- Из-за различий реализации PhysicsServer3D некоторые функции, в том числе
  SoftBody3D и VehicleBody3D, могут вести себя по-разному на разных бэкендах.
  Такие различия — предмет проверки, а не гарантированное одинаковое поведение.
- Повторяйте стресс-тест с разным числом тел и записывайте FPS, время
  физкадра и RAM через встроенный Profiler; один FPS без baseline
  не доказывает улучшение производительности.

`lab_2d.gd`, `environment_3d.gd`, `environment_2d.gd`,
`buoyant_box.gd` (старый пример), `walker_2d.gd`, `smoke_test.gd`.

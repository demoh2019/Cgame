# Cgame — нативная физика кривизны гибких стержней

Небольшая сцена для проверки нового **3-точечного ограничения изгиба
центральной линии стержня** в GodotPhysics3D. Она содержит узкую,
изначально изогнутую деформируемую ленту и шар для ударного воздействия.

## Запуск

Из корня Cgame после сборки актуального `develop`:

```sh
git checkout develop
git pull origin develop
./bin/godot.macos.editor.$(uname -m) --path demo/rod_curvature_lab
```

**Space** — толкнуть синий шар в сторону ленты.
**R** — перезапустить. **Esc** — выход.

Smoke-тест:

```sh
./bin/godot.macos.editor.$(uname -m) --headless --path demo/rod_curvature_lab --script res://smoke_test.gd
```

## Что делает C++-солвер

Включение в разделе `[physics]` файла `project.godot`:

```ini
3d/physics_engine="GodotPhysics3D"
3d/solver/soft_body_xpbd_compliance=0.00002
3d/solver/soft_body_xpbd_rod_bend_compliance=0.000003
3d/solver/soft_body_xpbd_rod_straightness=0.93
```

- `rod_bend_compliance=0` **полностью отключает** новый механизм
  (это значение по умолчанию для остальных проектов).
- `rod_straightness=0.93` выбирает соседние исходные рёбра,
  направленные почти навстречу друг другу (прямолинейные цепочки).
  Порог можно уменьшить до `0.7` для более сильно изогнутых
  исходных цепочек. Диапазон `0..0.9999`.
- На один центр выбирается не более **двух непересекающихся пар**
  исходных рёбер. Это ограничивает количество дополнительных
  угловых ограничений на вершину и полезно для сеток с двумя
  ортогональными направлениями армирования.
- В отличие от стандартного «двухшагового» расстояния, XPBD
  теперь сохраняет **угол между двумя последовательными
  сегментами**, а не только расстояние между их концами.
- Исходный угол измеряется при построении топологии;
  поддерживаются немного изогнутые исходные цепочки.
- Угловой множитель Лагранжа сохраняется между итерациями
  внутри одного шага и обнуляется перед следующим шагом.
  Нулевые обратные массы (прикреплённые вершины) не меняются.
- Расчёт построения ограничений разовый, по рёбрам исходной
  треугольной поверхности. Нет дополнительного поиска соседей
  в горячем цикле симуляции; нет выделения памяти при вычислении
  самой угловой коррекции.

### Сравнение

В `project.godot` переключайте `rod_bend_compliance`
между `0` и `0.000003`, не меняя массу, `xpbd_compliance`,
частоту физики или геометрию. Новый режим должен по-другому
сопротивляться изменению кривизны, особенно при ударах.

## Ограничения

**Это ещё не полный Cosserat rods-солвер.** У стержней есть только
поступательные координаты трёх частиц, без независимых ориентаций
сегментов (кватернионов), угловой инерции, кручения, twist/bend
связи и столкновений между тонкими круглыми стержнями.

Новый режим работает с **цепочками, найденными внутри существующей
треугольной сетки SoftBody3D**. Он пока не создаёт самостоятельные
1D-объекты Rope3D и не умеет импортировать произвольные линии без
полигональной оболочки. Платформы, использующие Jolt, не затронуты.

Нативные C++-тесты: `tests/servers/test_physics_xpbd_rod_bend.cpp`.
Численные и структурные контракты:
`tests/stress/test_physics_xpbd_rod_bend.py`.

Следующий этап для настоящего Cosserat solver — материал-фреймы
и `SO(3)` поворотные степени свободы каждого сегмента, с XPBD
bend/twist constraints и корректной передаче углового момента.

# Aurora Forest: playable 3D graphics reference for Cgame

This directory is a **standalone playable reference project**, not a replacement for the user's existing game. It showcases engine capabilities using stock Godot resources plus the native `AdaptiveResolution3D` node introduced by [PR #907](https://github.com/demoh2019/Cgame/pull/907) and the fork's existing `WorldPartition3D` module.

## Features integrated into this demo

- Deterministic rolling terrain with vertex normals derived from an analytic heightfield and vertex-colored PBR material.
- **Real terrain NavigationMesh streaming:** each full-detail forest cell can own a native filtered 16×16 terrain-height NavMesh (up to 512 triangles) inside NavigationRegion3D, synchronizing with adjacent streamed tiles. Cgame activates/demotes regions independently using `navigation_radius=1`, hysteresis and at most two region switches per frame. Distant low-importance cells avoid active NavMesh work; important/urgent travel destinations force navigation activation and await a two-physics-frame readiness barrier. Stalkers request genuine NavigationServer3D paths on native navigation CPU grants, cache waypoints between requests, and preserve raycast collision avoidance. HUD displays active nav-region cells and fast-travel NavMesh readiness. The native generator rejects triangles near tree/rock collision footprints expanded by NPC radius, and excludes steep slopes; 3D capsule clearance, dynamic obstacles and exact polygon carving are not yet guaranteed.
- **Exact incremental NavMesh patches:** the native WorldPartition3D tile builder now compares old and new tree/rock/barricade footprints, automatically unions just the changed obstacle influence areas and re-evaluates only their triangles. Unaffected cached triangles retain their walkability; a no-change footprint set returns the existing resource. Full 16×16 terrain tiles test 512 triangles, while a local B-key barricade typically re-tests a fraction of these, visible in the HUD's triangle-work counter. The streamed cell caches obstacle footprints and uses the engine patch API without resampling the terrain during a dynamic update. A new headless smoke verifies exact polygon equality to a full build for addition, movement and removal.
- **Interactive dynamic obstacles and in-place NavMesh rebuild:** press **B** to add/remove a collidable wooden barricade in the current loaded forest sector. Its circular footprint feeds the native C++ NavMesh builder; `WorldPartition3D.mark_cell_navigation_dirty()` schedules the updated mesh under a strict **one rebuild per physics frame** budget, coalescing duplicate marks. The barricade exists as real StaticBody3D collision plus visible geometry. No cell unload or foliage re-spawn is needed. HUD reports pending nav rebuilds; NPCs invalidate their cached navigation path using a monotonic world generation counter and re-query under existing native steering grants. A successful refresh must wait two physics frames before being considered safe for travel/navigation.
- **Obstacle-aware engine NavMesh baking:** the new native C++ `WorldPartition3D.build_navigation_tile()` builds deterministic slope-limited mesh triangles with exact planar triangle-versus-disc checks (tree trunks and rock bounds enlarged by the NPC radius). Forest cells gather their own obstacle footprints from the same deterministic generation that creates collider shapes. A reserved central forest trail maintains seamless travel between streamed tiles; the broader woodlands remain densely decorated outside this corridor. A 16×16 tile bounds generated polygons, and extra radius reduces the walkable area rather than relying solely on the raycast AI fallback.
- **Cross-cell quest corridors:** the native `WorldPartition3D.find_cell_path()` searches registered grid cells with a bounded 512-cell BFS. If the objective is several cells away, the Aurora Forest quest compass now guides the player toward the center of the next registered corridor cell and shows remaining sector hops instead of pointing through a missing terrain cell. A live-only route filter is also available for future NPC streaming; no surface NavMesh or collision-free guarantee is implied.
- **Native-budgeted stalker navigation:** C++ WorldPartition3D grants at most **2 expensive NPC steering recalculations per physics frame** across active forest cells. Stalkers register under stable encounter IDs, reuse cached direction between grants, perform 1–3 obstacle raycasts per approved update, and continue CharacterBody3D physics every tick. Native priority + least-recently-selected scheduling distributes the work; deleted/respawned enemies unregister safely without evicting replacements. The HUD displays used/max navigation slots. No navmesh has been baked: this is **local obstruction avoidance**, not global pathfinding.
- **Spatial physics-tier streaming:** the native engine keeps distant forest cells visually loaded while cell-specific collision bodies use `collision_layer=0` outside the physics radius. The `WorldPartition3D` policy is independent of render LOD and AI simulation. Pinned camps and urgent/important streaming targets force physics activation and full-detail collision; regular/background relic preloads do not. HUD reports active physics-cell count. F10/F11 travel additionally checks `is_streaming_source_physics_ready()` after the physical-frame delay, so movement waits for enabled colliders rather than just allocated scene roots.
- **Physics-stabilized gameplay activation:** Cgame's native `WorldPartition3D` requires at least **two physics ticks** after instantiating a streamed scene and can query its opt-in `is_streaming_activation_ready()` predicate. Aurora Forest scenes verify that near-detail obstacle collision nodes have been built. **F10/F11** travel now checks this stricter activation fence and the separate physics-ready source gate, and combat encounter creation waits for the same gate; the HUD displays both loaded scene and activation progress. Fast travel still uses the persistent heightfield ground to choose a known surface; this is not a generic navmesh or physics-server fence.
- **Simulation-aware AI and scene effects:** `WorldPartition3D.simulation_radius=1` independently marks near cells active; `simulation_hysteresis_cells=1` prevents frequent AI switching at boundaries and no more than 2 existing cells change activation each frame. Forest enemies now consult the **native simulation policy** rather than graphical LOD. Remote quest/fast-travel scenes remain visible/preloaded but do not spawn enemies before the player approaches; F4 visual quality toggles do not wake all AI. The home beacon's subtle light pulse runs only if its cell is simulation-active. HUD displays the number of actively simulated cells.
- **Priority-aware world streaming:** Aurora Forest uses priority **3 (urgent)** for F10/F11 travel destinations and **0 (background)** for the nearest relic's quest-preload source. They compete under the original per-frame loading limits, while the main player neighborhood and pinned hub always take precedence. This makes source priority a visible engine feature rather than an unused inspector/API setting.
- **Nonblocking fast travel staging:** **F10** starts travel to the active relic, **F11** back to the home clearing and **F12** cancels. A temporary named `WorldPartition3D` source keeps the destination cell scheduled while the HUD reports instantiated-scene progress. The player can keep moving and fighting during background streaming; the move occurs only after every native source scene is loaded, its minimum physics-frame delay has elapsed, and the scene-defined predicate reports ready. Errors, unregistered cells, cancellation and 10-second timeout clean up the source and do not teleport. The showcase terrain itself remains statically loaded; production terrain, physics and navmesh readiness need separate fences.
- **Playable streamed combat encounters:** deterministic per-cell forest stalkers use capsule CharacterBody3D physics, chase/leash behavior, close-range attacks with cooldown, three-hit HP, and a visible emissive-eye material. The encounter director limits the world to **5 spawned NPCs**, scans simulation-active **and physics-activation-ready** cells only every 0.35 s, enables physics only within 24 m and removes enemies when cells unload. The player has 100 HP, short hit invulnerability, and respawns safely at the camp on defeat. **F / left-click while mouse is captured** swings at physics-visible opponents (blocked by trees/terrain). Each defeated encounter is saved and never respawns after streaming reload.
- **Relic quest navigation + remote cell preloading:** the game chooses the nearest remaining relic, remembers it until collection, shows a luminous waypoint and player-relative compass/distance in the HUD, and keeps its remote forest cell prepared through a named native source. Collecting a relic selects the next target; finishing all eight removes the extra loading source. Progress remains derived from existing saved relic IDs.
- **Seam-resistant LOD:** native `detail_hysteresis_cells = 1` means an already-full-detail forest cell stays full for an extra ring before demotion; the original inner radius remains the promotion threshold. This reduces rapid foliage/collider reconstruction when the player moves back and forth near boundaries.
- **Distance LOD forest:** with a 2-cell streaming radius, the inner 1-cell radius uses 54 trees, 225 grass tufts, 9 rocks and local obstacle colliders per cell, while outer cells use 16 deterministic tree silhouettes with cheaper foliage meshes and no per-tree physics or shadows. Pinned home hubs stay full-detail even when far away. **F4** toggles the native detail system and the HUD counts distant cells.
- **Predictive scene streaming:** Aurora Forest feeds the first-person character's velocity into the native streamer. A bounded 2.5-second / 28-meter lookahead requests one upcoming cell before crossing its border, after visible and pinned cells. The HUD shows the target and **F3** toggles this feature for A/B comparison.
- **Persistent home clearing:** native `pin_cell(Vector2i.ZERO)` retains a home hub even outside the unload radius, with a low-cost emissive beacon, a shadow-free OmniLight and a pinned-cell HUD counter. Removing a pin returns the cell to ordinary unload behavior (verified by the streaming smoke test).
- **WorldPartition3D streaming:** 16 registered 32 m × 32 m cells reference the **same** packed forest scene; the engine shares the threaded resource request, instantiates around the camera (one cell/frame) and unloads distant cells with hysteresis. The fork also exposes an `observer_cell_changed` event for region-aware gameplay; the demo displays the current cell without polling player coordinates.
- **Chunked GPU instancing:** each loaded cell generates up to 54 trees, 225 animated grass tufts, and 9 rocks using five or fewer MultiMesh draw groups, instead of one Node3D per instance. At most 3,600 grass tufts exist if all 16 cells are loaded.
- **Day/night and weather:** a 16-minute 24-hour clock drives directional sunlight, AgX sky colors, ambient energy, fog and cloud coverage twice per second. Clear, overcast and mist presets; nighttime procedural north-facing aurora ribbons are rendered without a `TIME`-dependent sky shader. F6 cycles weather, F7 pauses time and F8 jumps 3 in-game hours. Time and weather are saved in backward-compatible v1 save files.
- Atmospheric procedural sky with the DirectionalLight3D sun, stable ambient sky radiance, cinematic AgX tone mapping, optional SSAO, SSIL, volumetric fog, and glowing collectible crystals.
- **First-person physics:** a capsule `CharacterBody3D` controller with frame-rate-independent gravity, grounded and air acceleration, sprinting, jumping, slope snapping and mouse look; collision from the terrain's generated triangle mesh plus dynamically streamed tree-trunk and boulder primitives.
- Exploration, eight collectible forest relics, HUD with loaded cell count, and interactive high/performance profiles.
- **Versioned local saves** under `user://` storing collected relics, camera and quality settings. `F5` saves, `F9` loads, collecting a relic automatically saves; invalid JSON or incompatible versions are rejected.
- Live 3D resolution scaling to a 60 FPS target using the fork's native GPU-time adaptation. When valid GPU timings are unavailable, the adaptive node deliberately does not change resolution.

## Run

1. Build Cgame from branch `feature/cgame-physics-activation-fence-20261120-gpt6` (or after PR #907 and all dependent engine/game PRs are merged). This showcase uses the newer native `WorldPartition3D` source-readiness API alongside `AdaptiveResolution3D`; the original #907 branch alone is insufficient.
2. Open this **folder**, `misc/cgame_forest_showcase`, as a separate Godot project with that Cgame editor executable.
3. Use the Forward+ rendering backend and click Play. The project uses FSR2 and expects the selected rendering backend to support it.
4. Press **F10** to stage a fast-travel to the currently marked relic, **F11** to return to the camp, or **F12** to cancel while streaming. The progress line in the HUD shows ready/total destination scenes; you can keep moving during staging. A missing scene never causes an immediate jump.
5. Approach forest stalkers, aim at their glowing eyes and press **F** (or left-click while mouse is captured) to strike. Three hits defeat a stalker. Enemy attacks reduce HP, while defeat returns you to the safe home clearing without clearing relics or defeated-enemy progression.
6. Follow the glowing blue objective beacon and the direction/distance indicator in the HUD. Collect with E to retarget the next relic. A dedicated streaming source prepares the quest cell remotely.
7. Click inside the window to capture the mouse. **WASD / arrow keys** move, **mouse** looks around, **Shift** sprints, **Space** jumps, **E** picks up nearby crystals, **F5/F9** save/load, **Esc** releases the mouse.
8. Press **F6** to cycle clear/cloudy/mist, **F7** to pause/resume the day/night clock and **F8** to jump ahead 3 in-game hours. Changes are shown in the HUD and persist across save/load (F5/F9).
9. Press **F4** to enable/disable near/far cell detail and compare GPU cost, CPU physics and memory use. When disabled, all loaded cells return to full detail under the 2-transitions/frame budget.
10. Press **F3** to enable/disable velocity-driven prefetch. In the HUD, an upcoming coordinate means a distinct next cell; `—` means no distinct forecast, and `OFF` means the feature is disabled.
11. Press **F1** for the cinematic profile (SSAO, SSIL, volumetric fog and all grass), **F2** for the performance profile (less grass, no SSAO/SSIL/volumetric fog). GPU-budget scaling runs in both.

## Technical constraints

The demo is deliberately small and asset-free. Its spheres, cylinders, quad blades and procedural sky are placeholders for real authored assets; it does **not** reimplement Unreal Nanite/Lumen. A full game should replace these with authored PBR meshes, materials, impostors/HLOD and a complete tile-based terrain + texture streaming solution. The effect budgets should be tuned with GPU measurements on actual target devices.

A `MultiMesh` is culled as one unit; therefore trees and grass are split into 16 **streamed local cell scenes** instead of one massive draw group. This sample still retains a single terrain/collision mesh, shared materials and all eight collectibles when distant; a production open world needs terrain and gameplay entity streaming, true HLOD/impostors, collision/navmesh warmup and origin management. Primitive colliders are re-created with each streamed cell; their counts should be profiled as world density increases. `WorldPartition3D` does not provide these automatically. The native `AdaptiveResolution3D` class is opt-in and should be used only once per viewport.

footprints, and lower triangle-filter evaluation counts. `smoke_dynamic_navmesh.gd` additionally checks that a real B-key forest barricade uses the incremental path, yields the same polygons as a complete rebuild and does not reload the forest scene. `smoke_dynamic_navmesh.gd` validates creation/removal of a real barricade and collision, native dirty queue coalescing and strict frame budget, two-physics-frame readiness, new NavigationMesh publication without reloading the cell, restored walkable polygons, global topology generation changes and NPC cached path invalidation after a remote tile rebuild. `smoke_navigation_clearance.gd` tests the real native C++ clearance and slope algorithm, compares agent radii, checks shared boundary samples and verifies that actual forest navigation meshes reject polygons around the same tree/rock footprints used for collision. `smoke_navmesh_streaming.gd` checks actual triangulated NavigationMesh regions, NavigationServer3D path across adjacent streamed tiles, priority 0 vs 3 activation, region demotion without visual unload, hub pinning and default -1 compatibility. `smoke_encounters.gd` waits for navmesh region readiness as well as physics stabilization. `smoke_cell_routes.gd` verifies true C++ shortest cardinal corridors in a sparse registered map, missing/disconnected cells, shortened routes after adding a shortcut, intermediate quest waypoint placement and the loaded-only guard. `smoke_navigation_avoidance.gd` adds a real StaticBody3D obstacle in the enemy's approach path and tests that the physical raycast detects it and that the CharacterBody3D actually steers laterally without any WorldPartition3D. `smoke_navigation_budget.gd` tests real physics-tick probes and native agent scheduling: fixed 1–2 grants/frame, equal-priority fairness, strict urgent priority, dormant actor skipping, remote cell eligibility, replacement-owner safe unregister and a real stalker's scheduled steering. `smoke_encounters.gd` checks NPC registration, unload/reload cleanup and defeated enemy removal; `smoke_combat.gd` verifies standalone fallback. `smoke_physics_tiers.gd` tests real native physics-tier classification, collision-layer filtering while visual MultiMesh remains alive, PhysicsServer raycasts, urgent source forcing near LOD and collider activation, low-priority preload, hysteresis, pin/unpin and the backward-compatible default. `smoke_activation_fence.gd` uses dedicated probe PackedScenes to verify that the native physics-frame barrier and scene-defined readiness callback both gate activation. It also checks progress, destination retargeting, revocation without unloading, and source cleanup. `smoke_encounters.gd` now waits for the activation fence on initial load and after reload. `smoke_simulation.gd` exercises actual streamed forest roots: near-only activity, optional callback called before `_ready()`, independent visual geometry, existing-cell transition budgets, hysteresis, pinned hubs, and opt-out reactivation. `smoke_source_priorities.gd` checks actual observer-first, urgent-second and background-last scene instantiation when all three cells share one PackedScene and `max_instances_per_frame=1`. It also checks runtime priority updates and source cleanup. `smoke_quest.gd` and `smoke_travel.gd` verify the chosen background and urgent priorities in their respective game systems. `smoke_travel.gd` verifies actual destination scene readiness, teleport only after resource instantiation, cancellation, unregistered scene rejection and timeout without modifying persistent saves. `smoke_sources.gd` now also verifies loaded/failed counters and invalidation after moving a source. `smoke_combat.gd` verifies real CharacterBody3D pursuit/attack, dormant AI, melee damage and a killed enemy signal. `smoke_encounters.gd` exercises live native cell-root lookup, streamed NPC spawn/despawn, stable defeat ID and saved-state restoration. `smoke_saves.gd` also checks defeated ID round-trips, rejects malformed/duplicate/out-of-world entries and retains compatibility with older v1 saves. `smoke_sources.gd` loads and releases a distant quest scene using an independent source, including updates and cleanup. `smoke_quest.gd` validates nearest-target choice, compass bearing, distance, retargeting and source lifecycle without writing a save. `smoke_streaming.gd` checks motion prefetch before the observer crosses a cell boundary, persistent home-cell pinning and unpinning, async shared-cell load/unload/reload, deterministic per-cell instance transforms, negative grid coordinates, streaming obstacle collision and performance density. `smoke_saves.gd` uses a separate throwaway save path, checking round-trip, deduplication, invalid JSON and version rejection. `smoke_lod.gd` verifies actual near/distant foliage generation, stable transforms across tier switches, pinned hubs retaining full detail, disabling LOD and LOD hysteresis at grid boundaries. `smoke_atmosphere.gd` checks night aurora, sunlight, weather presets, clock wrap-around, pausing, shader uniform updates and the 0.5s sky-work throttle. `smoke_physics.gd` instantiates the real scene, queries static terrain collision and checks that a spawned character falls onto the terrain; it also checks that obstacles are constructed in streamed cells. These tests are **added, not claimed to have been executed**.

## Verification checklist

- [ ] Engine compiles with the new native node, in both tools and template builds.
- [ ] Demo imports and scene starts with no errors on Cgame's Forward+ renderer.
- [ ] Sky shader compiles on Vulkan and Metal (note: `sky()` has no early `return`).
- [ ] Wind, grass instancing and sky render correctly on Apple M1.
- [ ] Compare actual nav triangle re-tests in the HUD after B-key barricade changes (full tile: 512) against the completed polygon array and CPU timing; check that unchanged blocker lists do not republish NavigationMesh.
- [ ] Press B in multiple forest sectors to check live barricade collision and dynamic NavigationMesh updates; watch pending tile count and verify that previously cached stalker routes replan only under their native steering grants. Compare the cost of full tile regeneration to existing CPU budgets.
- [ ] Inspect clearance-carved NavMesh around tree trunks, rock boxes and the central forest trail; compare radius 0.0, 0.45 and 1.1 and slope limits. Check that terrain seam paths remain connected after filtering and test input bounds on invalid samples.
- [ ] Verify actual neighboring NavigationRegion3D polygons connect after server sync; profile path queries at 1/2/5 stalkers and check that tree collisions are still avoided. A future proper bake must carve tree/rock obstacles and shrink the mesh to the agent's radius.
- [ ] Verify quest heading for a relic across several streaming cells, missing corridor cells, and a newly opened shortcut; do not mistake the topological cell corridor for a walkable NavMesh.
- [ ] Profile stalker steering query counts per physics frame with 1, 2 and 5 enemies and budgets 1, 2 and 5; check priority, equal-priority fairness, and obstacle deflection. Baked navmeshes and cross-cell pathfinding remain future work.
- [ ] Test native physics radius/hysteresis under movement: distant geometry must remain visible while collision is excluded from physics queries; F10 must wait for urgent destination full LOD, the collider state and one completed physics tick. Record physics CPU costs rather than assuming an FPS gain.
- [ ] Validate F10/F11 activation readiness after at least two physics ticks, callback failure/recovery and repeated scene unload/reload. The demo's persistent terrain permits its known-safe spawn; streamed collision and navmesh still require game-specific readiness validation.
- [ ] Observe the simulated-cell HUD near cell boundaries and verify only near AI runs, the pinned home cell remains active, F4 visual LOD toggling does not wake distant NPCs, and default -1 radius restores prior behavior.
- [ ] Compare remote quest background loads versus urgent F10 destinations with `max_instances_per_frame=1`; confirm observer and pinned hub cells remain first and record frame times under competing sources.
- [ ] Verify F10/F11/F12 on Apple M1/Metal and headless: loaded scene gating, valid terrain position, no transport to missing cells, cancellation and timeout. Check that the original gameplay remains responsive while staging.
- [ ] Test F/left-click combat against stalkers, player hit cooldown and camp respawn, defeated-enemy save/load, no respawn on cell re-entry, and no NPC physics outside the 24m activity radius.
- [ ] Profile CPU physics time with a 5-NPC near-cell limit, confirm raycast occlusion and camera feel on Apple M1/Metal.
- [ ] Verify relic quest beacon and compass after starting, collecting relics and loading a save. Observe that quest source does not keep old cells loaded after retargeting.
- [ ] Check F6/F7/F8 day-night and weather changes in Forward+/Metal, including the sky shader and light probes; compare radiance reprocessing cost at the 0.5-second update interval and frame spikes.
- [ ] Check old v1 save data still loads, and that atmosphere state returns after an explicit save/load.
- [ ] Confirm F4 changes distant tree count and removes/restores distant grass and colliders without duplicates; profile FPS, GPU milliseconds, CPU frame time and VRAM on Apple M1/Metal.
- [ ] Confirm F3 toggles prediction and run a repeated sprint path while comparing scene load delay, FPS and memory usage in both modes.
- [ ] The (0,0) home beacon remains loaded beyond the unload radius; unpinning it allows unloading, and pinning cannot exceed 128 cells.
- [ ] Walking through cell boundaries updates the loaded-cell HUD, preserves terrain/foliage alignment, and unloads/reloads cells without flicker.
- [ ] Verify capsule grounding, jumping, collision against trunks/rocks, world bounds, camera position and save/load after teleporting.
- [ ] Run all twenty-one headless smoke scripts on the compiled fork.
- [ ] Picking up eight crystals updates the HUD, the savegame persists after reopening, and profile switching changes measured GPU time.
- [ ] Confirm that GPU timings are available and adaptive resolution reacts to sustained load.
- [ ] Record frame time, GPU time, FPS, and VRAM in F1 and F2 profiles, using the same camera path.

These checks are not claimed complete until running the project on a compiled build.

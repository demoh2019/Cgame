# Incremental Content Delta Bundles

This tool adds **deterministic ZIP bundles of changed content** to the Content Delivery manifest foundation (#61, item 43). Like the manifest tool, it is Python-standard-library-only.

Use two validated version-1 manifests generated by `content_manifest.py`. Build the archive from the **new** release directory:

    python3 misc/scripts/content_delta_bundle.py build old.json new.json /path/to/new-game --output changes.zip
    python3 misc/scripts/content_delta_bundle.py verify old.json new.json changes.zip
    python3 -m unittest discover -s misc/scripts/tests -p 'test_content_delta_bundle.py' -v

The archive contains only *added and changed* files, with portable relative ZIP member names in sorted order. Files which are unchanged are omitted. Deleted paths appear only in the old/new manifest difference: there are no deletion commands in the archive. The ZIP is stored uncompressed to produce reproducible bytes independent of compression-library versions.

`verify` checks exact membership, order, lengths, file types and SHA-256, without extracting any archive entries. `build` rejects symlink paths, mismatched source bytes, and a destination which would overwrite a packaged file. Output is written using atomic replace so failed builds preserve the prior bundle.

**Security boundaries:** Neither the ZIP nor the SHA-256 manifest authenticates the publisher. Deliver manifests and archives through authenticated channels or add signatures before using in production. This utility never downloads, extracts, installs, deletes, or rolls back assets; consuming a bundle requires a separate, safely staged installer. Build from an immutable source tree to avoid filesystem races. ZIP paths are validated by the existing manifest validator. Bundles deliberately carry no executable install instructions.
